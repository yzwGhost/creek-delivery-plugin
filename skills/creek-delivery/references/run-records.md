# run-records

新需求先确认版本号和需求名称，生成文档统一存放在 creek-qiankun 项目根目录 `PRD/<版本号>/<需求名称>/`。用户或资料明确给出版本时按原样使用；版本不明或资料冲突时询问用户，答复前不创建该需求目录。不得自动合并或改名现有版本目录。目录按需创建，不覆盖现有文件：

```text
PRD/<版本号>/<需求名称>/
├── 01-资料/资料清单.md
├── 02-需求分析/需求与资料核对表.md
├── 02-需求分析/开发任务与分工.md
├── 03-测试/测试计划.md
├── 03-测试/测试用例.md
├── 03-测试/测试执行记录.md
├── 03-测试/缺陷记录与回归表.md
├── 03-测试/证据/{截图,日志}/
├── 04-云效/测试用例同步清单.md
├── 04-云效/缺陷同步清单.md
├── 05-交付/交付报告.md
└── 运行记录/<批次标识>/
```

资料清单记录原始资料位置与版本；证据脱敏。未发生的阶段不创建空文件。重复需求或批次使用唯一标识，保留历史。已有批次恢复时沿用其原路径和快照，不自动迁移；迁移按原有确认规则执行。

每批在项目交付记录目录创建唯一子目录，运行 scripts/workflow.py start <批次目录> 固定 workflow.json 和 references 的完整副本。恢复时从该批次当前快照读取规则。记录资料版本、REQ/PAGE/API/CASE/BUG 稳定 ID、双向追踪矩阵、每阶段的负责人、依赖、状态、产物、证据和恢复条件。追加交接与验证历史。可用状态为待执行、执行中、完成、失败、阻塞。进程中断后核对实际产物与证据，再调度未完成项。迁移先用 diff 展示配置和规则差异，再列出影响阶段、重验范围和恢复计划。用户确认该差异后才可迁移。
