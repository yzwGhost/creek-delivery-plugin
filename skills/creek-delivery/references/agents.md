# agents

编排 Agent 持有唯一批次状态写权限，读任务图，分配文件所有权，合并交接、报告。需求设计 Agent 根据资料形成追踪与任务；测试设计 Agent 根据需求和原型产出用例与覆盖矩阵；后端及前端 Agent 根据任务和契约分别提交路由、页面与自检证据；测试修复 Agent 消费代码、契约和用例，记录执行、修复与回归；云效 Agent 仅消费确认清单，输出逐项结果。使用真实 spawn_agent 并保存返回的 Agent ID，通过 send_message 和 wait_agent 收集结果。每次分配列出输入版本、可写文件、依赖和验收条件；同一文件多个写者必须串行，跨端依赖契约先冻结。交接包含输入版本、修改范围、产物路径、验证结果、未决问题、下一步。工具或名额不可用时报告原因并将任务置为等待，不能以串行冒充并行。

按需求范围分配角色：无后端改动时跳过后端；无缺陷时记录依据并跳过修复和缺陷同步。一名子 Agent 可承担多个不冲突角色，但须保留真实多 Agent 分工及职责交接；不为无工作内容启动 Agent。跳过阶段必须记录原因，完成或有理由跳过的前置阶段可满足依赖；阻塞和失败不能视为完成。
