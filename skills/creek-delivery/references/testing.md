# testing

逐需求建立覆盖矩阵，每条用例记录稳定 ID、来源版本、关联需求、角色、前置数据、操作步骤及逐步预期；覆盖主流程、失败、边界、权限与状态变化。记录实际环境、构建版本、时间、执行者、实际值及脱敏证据。环境不可用时记录阻塞与恢复条件，未运行项保留未执行。失败保留首轮证据，区分产品缺陷、用例问题、环境故障与需求歧义。范围内确认的代码缺陷自动修复，记录变更并重跑原路径和受影响用例，保留每轮证据。资料版本变化时按稳定 ID 更新矩阵，标记受影响设计、开发和旧结果需复验；重新执行并重建有变更的云效清单，重新取得确认。

生成测试计划和测试用例时，分别使用批次快照中的 测试计划模板.md、测试用例模板.md，保留章节和字段；按实际需求复制用例明细，未知信息写待确认。模板随批次快照保存，恢复时使用原快照版本。

记录缺陷与回归时，使用批次快照中的缺陷记录与回归表模板.md，保留章节和字段及各轮执行历史；恢复时使用原快照版本。

需求与资料核对表作为需求追踪主表；测试计划引用覆盖摘要，测试用例引用需求编号，内容变化先更新主表。小需求可精简不适用的描述，但保留范围、环境、用例、结果、证据和阻塞结论；复杂需求填写完整模板。测试计划及用例统一使用 P0（核心阻断）、P1（重要功能）、P2（一般功能）、P3（低影响改善）。
