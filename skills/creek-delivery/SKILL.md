# Creek Delivery

首次运行先核对资料和仓库约束。恢复已有批次时，先读取批次保存的规则版本、阶段状态和交接记录。云效写入前展示完整清单，等待用户确认。

新需求的生成文档放在 creek-qiankun 项目根目录 `PRD/<版本号>/<需求名称>/`，目录结构遵循 run-records.md。版本号无法明确确定或资料冲突时，向用户询问，取得明确答复后再创建需求目录；不得猜测或合并已有版本目录。恢复旧批次时沿用原路径和快照。

在插件根目录执行 `python scripts/workflow.py start <新的批次目录>`。恢复时执行 `resume <已有批次目录>`，使用输出的配置和规则，依赖已满足的条目优先执行。按快照中的 intake.md 和 run-records.md 核对资料并建立台账；按 agents.md、development.md 分配角色与开发任务。按 testing.md 设计用例、联调、执行验收并修复回归。用例与缺陷同步分别遵循 yunxiao.md，按 delivery.md 汇总。禁止自动发布或操作生产环境。

确需迁移时执行 `python scripts/workflow.py diff <批次目录>`，逐项说明影响阶段与恢复计划，展示差异与摘要。仅在用户确认后执行 `migrate <批次目录> --confirmed-diff <该摘要>`。批次目录只由编排 Agent 写入。

云效写入须展示目标项目及本轮完整清单，并将用户确认绑定到项目、清单版本和内容摘要；更换项目或变更清单后确认立即失效，展示新清单并重新确认。迁移时 current 原子替换同时提交快照与迁移历史；中断后以 current 指向的版本恢复，忽略未提交的临时文件。

以下写入规则对每个批次强制生效。逐条先登记写入中，再调用实际工具，保存返回 ID、状态与时间。恢复时跳过已成功项；超时、中断或结果未知时，先按远端 ID 或稳定标记查询并比对完整内容。仅在权威查询证实未写入后可重试；无法判定、冲突或多重匹配标记待核对，停止该项。
用户确认绑定到目标项目、完整清单版本和内容摘要。更换目标项目或清单内容发生变化时，原确认失效，展示完整新清单并重新确认。
